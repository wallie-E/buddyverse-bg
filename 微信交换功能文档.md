# 微信交换功能文档

## 功能概述

微信交换功能允许用户之间互相交换微信号，采用双向确认机制确保双方都同意交换。

### 核心特性

- ✅ 双向确认机制：发起人和接收人都需要提供微信号才能完成交换
- ✅ 通知系统：发起请求和确认交换时都会发送通知
- ✅ 状态管理：支持待确认、已完成、已拒绝、已过期等状态
- ✅ 重新发起：发起人可以重新发送交换请求
- ✅ 隐私保护：只有双方都确认后才能看到对方微信号

## 数据库表结构

### wechat_exchange 表

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT | 主键ID |
| exchange_no | VARCHAR(64) | 交换流水号（唯一） |
| initiator_id | INT | 发起人ID |
| initiator_wechat | VARCHAR(100) | 发起人微信号 |
| receiver_id | INT | 接收人ID |
| receiver_wechat | VARCHAR(100) | 接收人微信号 |
| status | TINYINT | 状态：0-待确认，1-已完成，2-已拒绝，3-已过期 |
| initiator_confirmed_at | TIMESTAMP | 发起人确认时间 |
| receiver_confirmed_at | TIMESTAMP | 接收人确认时间 |
| completed_at | TIMESTAMP | 完成时间 |
| expired_at | TIMESTAMP | 过期时间 |
| created_at | TIMESTAMP | 创建时间 |
| updated_at | TIMESTAMP | 更新时间 |

### 通知类型（notifications 表）

新增两种通知类型：
- `wechat_exchange_request`: 微信交换请求
- `wechat_exchange_confirmed`: 微信交换已确认

**请求参数**:

### 2. 发起/更新交换请求

**接口地址**: `POST /api/wechat-exchange/request`

**请求参数**:
```json
{
  "targetUserId": 123,           // 目标用户ID
  "wechatId": "my_wechat_123",   // 我的微信号
  "isUpdate": false              // 是否是更新请求（可选，默认false）
}
```

**响应示例**:
```json
{
  "success": true,
  "code": 200,
  "message": "请求已发送",
  "data": {
    "exchangeNo": "WX17001234567890001",
    "status": 0,
    "notificationSent": true,
    "isNewRecord": true
  }
}
```

### 3. 确认交换

**接口地址**: `POST /api/wechat-exchange/confirm`

**请求参数**:
```json
{
  "exchangeNo": "WX17001234567890001",  // 交换流水号
  "wechatId": "my_wechat_456",          // 我的微信号（接受时必填）
  "action": "accept"                    // 操作：accept-接受，reject-拒绝
}
```

**响应示例（接受）**:
```json
{
  "success": true,
  "code": 200,
  "message": "交换成功",
  "data": {
    "exchangeNo": "WX17001234567890001",
    "status": 1,
    "otherWechat": "my_wechat_123",
    "completedAt": "2024-01-01T10:05:00.000Z",
    "notificationSent": true
  }
}
```

**响应示例（拒绝）**:
```json
{
  "success": true,
  "code": 200,
  "message": "已拒绝交换",
  "data": {
    "exchangeNo": "WX17001234567890001",
    "status": 2,
    "notificationSent": true
  }
}
```

## 业务流程

### 流程1：首次发起交换

```
用户A（发起人）                      系统                        用户B（接收人）
    |                                |                                |
    |--[点击交换微信按钮]------------>|                                |
    |                                |                                |
    |<--[调用 GET /info 返回无记录]--|                                |
    |                                |                                |
    |--[输入微信号并确认]------------>|                                |
    |                                |                                |
    |--[POST /request]-------------->|                                |
    |                                |                                |
    |                                |--[创建交换记录]                |
    |                                |                                |
    |                                |--[创建通知]-------------------->|
    |                                |                                |
    |<--[返回成功]-------------------|                                |
    |                                |                                |
    |                                |                [收到通知]<-----|
    |                                |                                |
    |                                |                [点击通知]<-----|
    |                                |                                |
    |                                |<--[输入微信号并确认]-----------|
    |                                |                                |
    |                                |<--[POST /confirm]--------------|
    |                                |                                |
    |                                |--[更新状态为已完成]            |
    |                                |                                |
    |<--[创建通知]-------------------|                                |
    |                                |                                |
    |                                |--[返回对方微信号]------------->|
    |                                |                                |
  [收到通知]                          |                                |
    |                                |                                |
  [可查看对方微信号]                  |                                |
```

### 流程2：重新发起交换请求

```
用户A（发起人）                      系统                        用户B（接收人）
    |                                |                                |
    |--[再次点击交换微信按钮]-------->|                                |
    |                                |                                |
    |<--[GET /info 返回待确认状态]---|                                |
    |                                |                                |
    |--[点击重新发送]---------------->|                                |
    |                                |                                |
    |--[POST /request, isUpdate=true]|                                |
    |                                |                                |
    |                                |--[更新确认时间]                |
    |                                |                                |
    |                                |--[创建新通知]-------------------->|
    |                                |                                |
    |<--[返回成功]-------------------|                                |
```

## 常见问题

### Q: 如何处理交换记录过期？

A: 可以添加定时任务，定期检查 `created_at` 超过一定时间且 `status` 仍为 0 的记录，将其状态更新为 3（已过期）。

### Q: 用户可以修改已提交的微信号吗？

A: 当前设计中，发起人可以通过重新发起请求来更新微信号。如果需要支持接收人修改，可以添加相应的接口。

### Q: 如何防止恶意用户频繁发起交换请求？

A: 可以在后端添加频率限制，例如：
- 同一用户对同一目标用户的请求间隔不少于 1 小时
- 使用 Redis 记录请求次数，超过限制则拒绝请求

### Q: 交换记录会永久保存吗？

A: 是的，当前设计会永久保存。如果需要定期清理，可以添加定时任务删除超过一定时间的已完成记录。

## 安全建议

1. **输入验证**: 确保微信号格式合法，防止 XSS 攻击
2. **权限验证**: 严格验证用户身份，防止未授权操作
3. **频率限制**: 添加接口调用频率限制，防止滥用
4. **敏感信息**: 微信号只在双方都确认后才能互相查看
5. **日志记录**: 记录关键操作日志，便于追踪和审计

## 扩展功能建议

1. **交换过期机制**: 添加自动过期功能，超过一定时间未确认自动失效
2. **撤回请求**: 允许发起人在对方确认前撤回请求
3. **黑名单**: 支持用户屏蔽某些用户的交换请求
4. **交换统计**: 统计用户的交换次数、成功率等
5. **多平台支持**: 除了微信，还可以支持 QQ、手机号等联系方式交换
